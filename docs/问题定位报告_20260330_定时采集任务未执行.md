## 根本原因分析

### 主要原因: Celery Beat 调度器问题

根据分析，**Celery Beat 调度器可能未正确运行**，原因包括:

1. **Beat 服务未启动**
   - `start_celery.bat` 只启动了 Worker，没有启动 Beat
   - 需要单独的命令: `celery -A config.celery beat`

2. **数据库调度与 Beat 同步问题**
   - django-celery-beat 使用数据库存储调度信息
   - 需要 Beat 服务从数据库读取并发送任务到队列

3. **队列配置不匹配**
   - start_celery.bat: `celery -A config.celery worker -l info -Q default,crawler`
   - celery.py 定义队列: default, workflow, crawler, vector, notification
   - Worker 监听的队列与任务发送的队列可能不匹配

### 次要原因: 配置不一致

- CrawlSchedule.crontab 存储的是旧配置（凌晨）
- PeriodicTask.crontab 使用的是新配置（晚上）
- 这种不一致不会导致任务不执行，但会造成管理困惑

### 方案一: 启动 Celery Beat 服务 (推荐)

**或使用 Flower 监控**:
```batch

```

### 方案二: 同步 CrawlSchedule 配置

```python
# 在 Django Shell 中执行
from apps.crawler.scheduler_models import CrawlSchedule
from django_celery_beat.models import PeriodicTask

for schedule in CrawlSchedule.objects.filter(is_active=True):
    pt = schedule.celery_task
    if pt and pt.crontab:
        # 同步 crontab 配置
        c = pt.crontab
        schedule.crontab = f"{c.minute} {c.hour} {c.day_of_month} {c.month_of_year} {c.day_of_week}"
        schedule.save(update_fields=['crontab'])
        print(f"已同步 {schedule.name}: {schedule.crontab}")
```

### 方案三: 修改 start_celery.bat 同时启动 Worker 和 Beat

```batch
@echo off
cd /d %~dp0backend
set DJANGO_SETTINGS_MODULE=config.settings.development

echo Starting Celery Worker...
start "Celery Worker" cmd /k "celery -A config.celery worker -l info -Q default,crawler,workflow,vector,notification"

echo Starting Celery Beat...
celery -A config.celery beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler
```
